# Worklog - 23 November 2026: cart emptied when changing category (1.7.9)

## Summary

The owner reported that the cart only ever held products from one category: adding a vibrator, then a dildo, left only the dildo. Reproduced on the dev server: add a product on `/vibrators`, open `/lubricants`, and the stored cart is empty before anything is added there. Release 1.7.9 fixes the cause in `ShopContext`.

## Why

Category pages (and product pages) pass `initialProducts` with only their own products; the full catalog is fetched from `/api/products` after hydration. The cart reconcile effect (added with the Supabase checkout migration) runs as soon as the cart is read from `localStorage`, searches each item in `products`, and dropped any item it could not find, treating "not in this list" as "deleted from the catalog". With a category-only list that was every item from another category, and the pruned cart was then written back to `localStorage`, so the loss was permanent.

## How

- `src/context/ShopContext.tsx`: new `catalogComplete` state, set true when `/api/products` answers. In the reconcile effect, an item whose product is not in `products` is kept unchanged while `catalogComplete` is false and dropped only once the full catalog is known. Items that are found still get the stock, variant and quantity checks. The effect depends on `catalogComplete` so it re-runs with the full list.
- `tests/category-dropdown.test.mjs`: text test for the flag, the guard and the removal of the old unconditional drop.
- Package 1.7.9, changelog. `CACHE_VERSION` unchanged.

## Where

- `src/context/ShopContext.tsx`, `tests/category-dropdown.test.mjs`, `package.json`, `CHANGELOG.md`, this worklog

## Testing

- Unit Tests: `node --test --experimental-strip-types tests/*.test.mjs` (115 pass).
- Manual Testing: dev server, cart built across `/lubricants`, `/dildos` and `/vibrators`; all three items survive each page change and show on `/checkout` with the right total.
- End-to-End Tests: after deploy, on vexatoys.com add one product from two different categories and open the cart; both must be there.

## Advanced Warnings

- A product that was deleted from the catalog is now removed from the cart a moment later (when `/api/products` answers) instead of at first paint. Same outcome, slightly later.
- The home page passes the whole catalog as `initialProducts`, so it never had the bug; a cart that looked fine from the home page could still be emptied by the next category page. That path is covered by the same fix.
