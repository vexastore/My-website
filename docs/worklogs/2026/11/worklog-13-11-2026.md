# Worklog - 13 November 2026

## Summary

Release `1.7.2` (Arabic guide and FAQ columns on `category_editorial`) merged as PR #13 and verified on production; the owner ran the column migration in Supabase. Arabic guide and FAQ drafts for all 23 categories delivered as `docs/sql/2026-11-13-category-editorial-arabic-drafts.sql` for the owner to review and run. No code change, no version bump.

## Why

The 1.7.2 columns are empty, so every `/ar/<category>` page still shows the short bilingual code content. The English editorial guides are 1,200 to 1,900 characters with three FAQs each; Arabic visitors had nothing equivalent, and the admin form cannot write the new columns yet.

## How

- Each Arabic guide was written from the English guide of the same row in Modern Standard Arabic, keeping the same facts: plain sealed box, cash on delivery, same-day Beirut and 24 to 72 hours elsewhere, 7-day return of unopened items, WhatsApp support. Store-count and price claims from the English copy were left out. Category names follow `src/data/categoryContent.ts` (for example "اير اصطناعي" for masturbators).
- Guides are 840 to 1,130 characters in three or four paragraphs separated by blank lines (the guide section renders `whitespace-pre-line`). Each row gets three FAQs (four for adult-toys), matching the English questions.
- Dollar-quoted (`$ar$`) so apostrophes and quotes in the text need no escaping; each `UPDATE` is guarded by `guide_ar = '' AND faqs_ar = '[]'`, so rerunning the file or running it after hand edits never overwrites owner-written Arabic.
- Validation: a script parsed every block, confirmed the 23 slugs match the live rows, loaded each FAQ array as JSON, checked for nested quote tags and stray Latin words; a second script ran every row through `parseCategoryEditorial`, `editorialGuideFor`, `selectCategoryFaqs` and `buildFaqPageSchema` from the storefront, confirming Arabic pages would get the Arabic guide and FAQs while English selection is untouched.

## Where

- New: `docs/sql/2026-11-13-category-editorial-arabic-drafts.sql`
- `docs/Database.md` (pointer to the drafts file), this worklog

## Production verification of 1.7.2

- Live bundle carries `CACHE_VERSION` `v1.7.2`; `/vibrators` and `/dildos` show their editorial FAQs and guide; `/ar/vibrators` and `/ar/dildos` show the four code FAQs with `lang="ar" dir="rtl"`, correct canonical and `en`/`ar`/`x-default` hreflang; all four served from the edge cache.
- Supabase verification query after the migration: 23 rows, `guide_ar_chars` 0 and `faqs_ar` 0 on every row.

## Testing

- Unit Tests: not run (no code change).
- Manual Testing: SQL block validation and storefront render check described above.
- End-to-End Tests: after the owner runs the drafts file, `/ar/<category>` should show the Arabic guide under "المزيد عن شراء ..." and the three Arabic FAQs within five minutes; the FAQPage JSON-LD on the Arabic page should carry the same three questions.

## Advanced Warnings

- The drafts are machine-written Arabic; a native reader should review tone and terminology before or soon after running, especially poppers, sexual-enhancers and chastity. Edits go straight into the Supabase table editor.
- The English adult-toys, sex-toys, dildos, male-toys and masturbators guides contain Arabic sentences, so `editorialGuideFor` hides the whole guide on those five English pages. `docs/sql/2026-11-13-english-guides-trim-arabic.sql` removes the Arabic paragraphs (guarded by the current text's md5 and a non-empty `guide_ar`) so the English guides show again.
