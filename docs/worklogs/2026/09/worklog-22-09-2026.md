# Task: Dynamic Category Buying Guide & FAQ Section (v1.5.7)

## Summary
Implemented dynamic category-specific Buying Guide and FAQ sections across the storefront. The section dynamically changes and updates in real time whenever the user is in or switches to any of the 22 categories or adult toys catalog. Backed by preloaded static editorial content in `src/data/categoryEditorial.ts` and live cached reads from Supabase `category_editorial` table. Restored Schema.org `FAQPage` structured data in JSON-LD on category and catalog routes matching the visibly rendered FAQs. Bumped `CACHE_VERSION` to `v1.5.7` in `lib/cacheVersion.ts` and `package.json` to `1.5.7` per Rule 8 in `AGENTS.md`.

## Why
The client requested that the bottom guide section be retained, but that it must dynamically adapt to whichever category the user is viewing or switches to. Previously, category pages rendered a server-rendered static guide outside of `ShopApp` that never updated when the user switched categories client-side. The client saw mismatched guides (e.g. seeing the Lingerie guide when viewing Vibrators) and requested that the guide section change dynamically based on the category.

## How
1. **Category Editorial Store (`src/data/categoryEditorial.ts`)**:
   - Preloaded all 23 category guides and FAQ sets from Supabase, sanitized all occurrences of "Vexa Store" to "Vexa Toys", and applied editorial punctuation cleanup.
   - Provides instant, synchronous client-side retrieval with zero network request waterfall or latency.
2. **Server-Side Fetcher Fallback (`lib/fetchCategoryEditorial.ts`)**:
   - Queries Supabase `category_editorial` table with `unstable_cache` (5-minute TTL, revalidated on `CACHE_TAGS.CATEGORY_EDITORIAL`).
   - Gracefully falls back to preloaded `src/data/categoryEditorial.ts` if Supabase is unreachable or in test environments.
3. **Dynamic Component (`src/components/CategoryGuideSection.tsx`)**:
   - Reads `activeCategory` and `initialCategorySlug` from `ShopContext`.
   - Resolves the current category slug via `CATEGORY_TO_SLUG[activeCategory]`.
   - Renders the category-specific Buying Guide, Frequently Asked Questions, and interactive quiz teaser.
   - Renders `RelatedCategories` pill row so users can quickly switch to related categories, instantly changing the guide and product list.
4. **Integration with `ProductList.tsx`**:
   - In `src/components/ProductList.tsx`, conditionally renders `<CategoryGuideSection />` when `activeCategory || initialCategorySlug` is set.
   - Renders the default homepage showcase (`BuyingGuideBanner`, `QuizBanner`, `RelatedCategories`, `FaqAccordion`) on the root homepage when no category filter is active.
5. **Route Integration & SEO (`app/[category]/page.tsx` & `app/adult-toys/page.tsx`)**:
   - Passes `initialCategorySlug={slug}` to `<ShopApp />`.
   - Fetches category editorial on the server and generates matching Schema.org `FAQPage` structured data in JSON-LD.
6. **Cache Invalidation & Version Bump**:
   - Bumped `CACHE_VERSION` to `v1.5.7` in `lib/cacheVersion.ts` and updated `package.json` to `1.5.7`.

# Task: Reload & Browser Anti-Caching Architecture (v1.5.8)

## Summary
Resolved client caching issues across mobile and desktop browsers by introducing multi-layered cache invalidation:
1. Configured HTTP `Cache-Control: no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0`, `Pragma: no-cache`, and `Expires: 0` headers for all HTML document routes and dynamic endpoints in `next.config.mjs`.
2. Added timestamp and version cache-busting parameters (`_t` and `_v`) to client catalog fetches in `ShopContext.tsx` to prevent iOS Safari GET request caching.
3. Added a `pageshow` event handler detecting `event.persisted` in `ShopContext.tsx` to immediately revalidate catalog data when mobile Safari or Android Chrome restores a page from the back-forward cache (bfcache).
4. Implemented automatic stale `localStorage` cleanup on app mount whenever `CACHE_VERSION` changes, evicting deprecated translation and temporary cache keys while safely preserving customer shopping carts and placed orders.
5. Added automated test in `tests/cache-version.test.mjs` verifying Next.js anti-caching headers for HTML routes and immutable caching for static chunks.
6. Bumped `CACHE_VERSION` to `v1.5.8` in `lib/cacheVersion.ts` and `package.json` to `1.5.8`.

## Why
The client and testing users reported seeing stale content or perceived caching issues when navigating or reloading the website on mobile and desktop devices. Investigation identified four factors:
1. Uncommitted/undeployed local changes: New category guides were implemented locally but not yet committed and deployed to the production environment, causing visitors on the live domain to hit the previous production build.
2. Browser HTML caching: Next.js by default does not set `no-store` headers on HTML page responses. Mobile Safari (iOS) and Chrome aggressively cache HTML shells in disk and memory cache, reusing old HTML documents that point to old JavaScript bundle hashes.
3. iOS Safari GET fetch caching: Mobile Safari can cache client-side `fetch('/api/products')` responses even when `cache: 'no-store'` is specified unless unique query parameters are supplied.
4. Mobile bfcache: Navigating back or switching tabs on iPhone restores frozen snapshots from bfcache without firing `useEffect` or `DOMContentLoaded`.

## How
1. **HTTP Headers (`next.config.mjs`)**:
   - Configured `async headers()` with two rules:
     - All HTML documents and API endpoints receive `no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0`, `Pragma: no-cache`, and `Expires: 0`.
     - Static assets (`/_next/static/*`) receive `public, max-age=31536000, immutable`.
2. **Catalog Fetch Cache Buster (`src/context/ShopContext.tsx`)**:
   - Appended `?_t=${Date.now()}&_v=${CACHE_VERSION}` to the `/api/products` fetch call.
3. **bfcache Detection (`src/context/ShopContext.tsx`)**:
   - Added `pageshow` listener checking `e.persisted` to trigger `refresh()` on bfcache restoration.
4. **Automated Version-Based `localStorage` Eviction (`src/context/ShopContext.tsx`)**:
   - Compares `localStorage.getItem('vexa_cache_version')` with `CACHE_VERSION`. Cleans up old translation keys (`vexa_ar_translations_*`) from earlier versions.
5. **Strict API Route Headers (`app/api/products/route.ts`)**:
   - Explicitly returns `Cache-Control: no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0`, `Pragma: no-cache`, and `Expires: 0`.
6. **Automated Testing (`tests/cache-version.test.mjs`)**:
   - Validates that `next.config.mjs` exports headers containing anti-caching directives for HTML routes and immutable directives for static assets.
7. **Cache Version & Documentation**:
   - Bumped `CACHE_VERSION = 'v1.5.8'` in `lib/cacheVersion.ts` and `package.json` to `1.5.8`.
   - Updated `CHANGELOG.md`, `README.md`, `docs/02-architecture/components/cache.md`, and daily worklogs.
