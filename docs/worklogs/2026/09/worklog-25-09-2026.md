# Worklog — 25 September 2026

## Summary

Fixed the client-reported checkout validation failure and inconsistent zero-review presentation. Product cards and product pages now use the real Supabase aggregate without invented fallbacks, and the product summary links to the genuine review form.

## Why

The checkout accepted a three-character address in the browser even though `/api/orders` rejected it, producing an opaque save failure. Product cards independently rendered five stars and a fallback count of 12 while the same product correctly showed zero reviews on its detail page.

## How

Centralized the order address boundary in `lib/orderValidation.ts`, reused it in the API and checkout form, propagated safe API errors through `ShopContext`, and added a targeted unit test. Replaced the card's hard-coded rating fallback with conditional real aggregate rendering, added a zero-review link to `#reviews-section`, removed `Rated 0/5` from client metadata, and bumped the cache/package version to 1.5.12.

## Changes Made

- Enforced the four-character address minimum before checkout submission.
- Preserved safe backend failure details and added an unavailable-item/cart-refresh message.
- Removed fabricated five-star and 12-review product-card fallbacks.
- Displayed an honest bilingual `No reviews yet` state on cards and product pages.
- Linked the product rating summary to the real customer review form.
- Omitted zero-review rating claims from runtime product descriptions.
- Bumped all centralized cache keys through `CACHE_VERSION` 1.5.12.

## Problems Encountered

Prior build artifacts were root-owned, preventing TypeScript and Next.js from updating generated files. The first browser checkout setup was also overwritten by the mounted page's empty cart state.

## Solutions

Moved only the generated root-owned artifacts to timestamped backup names and regenerated clean build outputs. Used an isolated Playwright context with seeded local storage for the checkout acceptance case.

## Bugs Found

- Browser/API address validation drift.
- Generic checkout errors hid safe item/option feedback.
- Product cards always drew five filled stars.
- A falsy zero count was replaced by `12`.
- Product metadata said `Rated 0/5` for unrated products.

## Bug Fixes

The shared validator prevents contract drift; safe errors now reach the UI; review rendering requires both a positive rating and approved review count; zero-review copy points customers to review submission.
