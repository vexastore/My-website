## Customer-Sent WhatsApp Checkout (11:28–11:34 Asia/Beirut)

### Summary

Replaced the checkout's fire-and-forget Telegram request with a customer-sent WhatsApp handoff after an acknowledged order write.

### Why

The client selected the regular WhatsApp app. The customer sends the prefilled order message to the store; both retain it in the chat. The previous checkout could show success before Firestore confirmed the order.

### How

`placeOrder` now awaits Firestore, retries once after anonymous reauthentication, and updates local order/cart state only after success. Checkout builds an encoded `wa.me` link from the saved order and offers it on the confirmation screen. The customer must tap Send in WhatsApp. Public Telegram relay and diagnostic routes were removed.

## Local Supabase Storefront Cutover and Verification (16 September 2026, Asia/Beirut)

### Summary

Connected the local public storefront to the imported Supabase catalog, articles, media references, and store settings. Added a server-side transactional checkout route and verified the failure path in a real local browser. No public storefront push or production deployment was made.

### Why

The user requested migration away from Firestore and explicitly required local testing before any public release. The previous client-side order path could diverge from the database and the imported admin data.

### How

Public RLS reads populate Next.js server pages and client catalog refresh. `/api/orders` validates same-origin JSON and calls `create_order` using a server-only secret; the browser retains its cart until the server confirms the order. Legacy cart product IDs reconcile to imported UUIDs. The old local admin route links to the separate admin application. Localhost bypasses the production canonical redirect in development.
