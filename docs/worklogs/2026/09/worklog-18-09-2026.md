## Product price freshness investigation and fix

### Summary

Prepared storefront 1.3.1 so published product pages refresh their selected product and catalog from an uncached Supabase-backed endpoint.

### Why

A client reported that an admin price change did not appear publicly. The product ID supplied for the audit event is archived; the independent cache path could also preserve stale prices on published product pages.

### How

The public product API now reads directly from Supabase and returns no-store headers. The client refreshes on load and tab return and reconciles the selected product by ID.

### When

18 September 2026, Asia/Beirut.

### Where

`lib/fetchProducts.ts`, `app/api/products/route.ts`, `src/context/ShopContext.tsx`, `package.json`, `package-lock.json`, `README.md`, `CHANGELOG.md`, `docs/features.md`, `docs/architecture.md`, `docs/API.md`, `docs/Testing.md`, `docs/09-project/known-issues.md`, and this worklog.

### Changes Made

Separated uncached client catalog reads from five-minute server-rendered SEO caching; synchronized selected product state and removed stale CDN response caching. Version 1.3.1.

### Problems Encountered

The supplied audit event did not identify a published product. Its row is archived at $280 and its public URL correctly returns 404. Concurrent TypeScript and build commands briefly conflicted over generated `.next/types` files.

### Solutions

Queried the exact row and compared 107 published database prices with the live public API; all matched. Reran TypeScript after the build completed. The archived row was not republished without owner direction.

### Bugs Found

The client held its initial selected product after fetching a newer catalog. The API also permitted stale CDN responses beyond its five-minute server catalog cache.

### Bug Fixes

The selected product now follows the fresh row, and the client API bypasses server/CDN caching.

### Testing

- Unit Tests: 12/12 storefront tests passed.
- Integration Tests: TypeScript and production build passed; local production API returned 200, 107 published products, and `private, no-store, max-age=0`; the archived ID was absent. A read-only comparison found zero price mismatches between 107 published database rows and the live API at investigation time.
- End-to-End Tests: headless Chrome with an intercepted catalog response changed a product price to $777 on hydration and $888 on tab return; both visible prices appeared. A separate mock removed the active product and the page showed “Product not found”.
- Manual Testing: the supplied archived product public URL returned 404 as intended.
- Coverage summary: current published catalog, archived exclusion, selected-product reconciliation, and tab return. No numeric coverage report.
- Edge cases: unavailable catalog keeps the prior visible state; archiving removes the selected product after a successful refresh.

### Performance Notes

Each page load and tab return now reads 107 published products directly from Supabase; server-rendered SEO pages retain the five-minute cache. No latency benchmark collected.

### Advanced Warnings

Server-rendered HTML and SEO metadata can remain stale for up to five minutes. A true cross-repository immediate invalidation mechanism is not installed. The owner must decide whether the archived product should be published.

## Storefront English/Arabic UX and navigation release (1.4.0)

### Summary

Localized the public shopping, blog, quiz, about, checkout, and order interfaces with English as the default and Arabic as the secondary language. Reworked catalog discovery, navigation, and the blog header.

### Why

Arabic text and direction appeared in English sessions, the homepage categories occupied too much space, navigation was long, the blog lacked a consistent header, and the homepage repeated its FAQ.

### How

The language switch stores a cookie so server-rendered and client-rendered sections agree on language and direction. The catalog has one category selector/search/filter row; the menu has a Products submenu and a transition. Shared blog navigation and localized page copy cover both languages. Display-copy normalization removes em dashes from fetched catalog/editorial content.

### When

18 September 2026, 11:12 Asia/Beirut.

### Where

### Bugs Found

### Bug Fixes

An earlier interactive browser pass verified category selection, search/filter placement, menu and submenu, language switching, and the single FAQ.

- Coverage summary: key public browsing routes and existing ordering/pricing utilities; no numeric code coverage collected.
